# Debt Manager Pro – مدير الديون والتحصيل الذكي

تطبيق Android مكتوب بلغة **Python 3** باستخدام **Kivy + KivyMD** وواجهة عربية
RTL، مع قاعدة بيانات **SQLite** وحسابات مالية دقيقة بـ **Decimal**.

> تم تنفيذ **المرحلة 1** (هيكل المشروع + قاعدة البيانات + الترحيل) و
> **المرحلة 2** (المدينون، الديون، الدفعات، الأقساط، الحسابات) بالكامل،
> مع 82 اختبارًا آليًا ناجحًا. المرحلة 3 (الرسائل والتذكيرات والجدولة) لم تبدأ
> عمدًا.

## ما تم تنفيذه

### المرحلة 1 — التهيئة وقاعدة البيانات

* هيكل مجلدات قابل للتوسّع للمراحل التالية.
* طبقة اتصال SQLite (`database/db.py`): اتصال لكل خيط،
  `PRAGMA foreign_keys=ON`، وضع WAL، معاملات صريحة عبر `BEGIN IMMEDIATE`
  ودعم المعاملات المتداخلة بـ SAVEPOINT.
* 14 جدولاً: المدينون، الديون، الدفعات، الأقساط، قوالب الرسائل، طابور
  الرسائل، سجل الرسائل، الجدولة، العملات، أسعار الصرف، إعدادات التطبيق،
  سجل التدقيق، العدادات، وسجل الترحيلات.
* علاقات `FOREIGN KEY` مع `ON DELETE CASCADE` حيث يلزم، فهارس على
  المفاتيح الأجنبية والتواريخ والحالات، وفهارس فريدة جزئية:
  * رقم الهاتف المنظَّف فريد (`ux_debtors_phone_key`).
  * رقم الإيصال فريد.
  * (debt_id, seq) فريد لكل قسط.
* مشغّلات (Triggers) على مستوى قاعدة البيانات تمنع:
  * دفعة تتجاوز أصل الدين أو تساوي صفرًا.
  * أقساطًا يتجاوز مجموعها أصل الدين.
  * ربط دفعة بقسط غير موجود أو غير قابل للدفع.
* ترحيلات مرقّمة (`schema_migrations` + `PRAGMA user_version`) قابلة للتطبيق
  أكثر من مرة دون تكرار، مع بيانات أولية: 10 عملات، 3 قوالب رسائل، إعدادات
  افتراضية، جدولة تذكير معطّلة.
* `buildozer.spec` و `requirements.txt` من البداية (minSdk 23).

### المرحلة 2 — إدارة المدينين والديون والدفعات والأقساط

**المدينون**
* إضافة/تعديل/حذف مع تأكيد، قائمة مع بحث فوري بالاسم أو الهاتف.
* منع التكرار بالمقارنة على الرقم المنظَّف:
  `+964 770 123 4567` و `00964-770-123-4567` و `9647701234567` رقم واحد.
* دعم الأرقام العربية/الإنجليزية (`٠٧٧…` = `077…`).
* الرقم الأصلي يُخزَّن كما أدخله المستخدم حرفيًا؛ التنظيف للمقارنة فقط.
* البحث بالاسم يتجاهل التشكيل ويوحّد (أ/إ/آ → ا، ى → ي، ة → ه).

**الديون**
* عدة ديون لكل مدين، عملة مستقلة، تاريخ الدين، تاريخ الاستحقاق، ملاحظات.
* حالة الدين: `open` / `partially_paid` / `paid` تُحسب من مجموع الدفعات.
* إجماليات لكل عملة على حدة؛ لا تُجمع عملات مختلفة أبدًا.

**الدفعات**
* دفعات جزئية وكاملة، تاريخ/وقت (UTC)، ملاحظات، رقم إيصال تلقائي
  (`R-YY-00001`) أو يدوي.
* تحديث فوري للرصيد والحالة، ومنع الدفع الزائد في الخدمة وفي قاعدة البيانات.
* سجل كامل بالدفعات مرتب من الأحدث.

**الأقساط**
* تقسيم المتبقي إلى أقساط متساوية مع توزيع الباقي بدقة على أول الأقساط
  (المجموع = المبلغ الأصلي تمامًا).
* تاريخ استحقاق شهري مع معالجة نهاية الشهر (31 يناير + شهر = 28/29 فبراير).
* القسط المتأخر يُشتق من التاريخ ولا يُخزَّن؛ الحالة المخزنة `pending` فقط.
* سداد القسط ينشئ دفعة مرتبطة به ويحدّث رصيد الدين وحالته.
* عند سداد الدين كاملًا تُلغى الأقساط المتبقية تلقائيًا (لإيقاف المطالبات).

**الواجهة**
* شاشات KivyMD: المدينون، تفاصيل المدين، نموذج المدين، نموذج الدين،
  تفاصيل الدين، إضافة دفعة، خطة الأقساط.
* RTL: ترتيب أفقي من اليمين لليسار، محاذاة يمين، وخط Amiri العربي مضمَّن
  (يغطي Arabic Presentation Forms)، مع تشكيل النص العربي
  (arabic-reshaper + python-bidi) لأن عارض SDL2 في Kivy لا يدعم bidi.
* إدخال النص العربي: `TextInput` في Kivy لا يعيد ترتيب bidi أثناء الكتابة،
  فيظهر النص داخل الحقل بترتيب بصري معكوس. لذلك تعرض حقول الاسم والملاحظات
  معاينة فورية ("كما سيُحفظ") أسفل الحقل. القيمة المحفوظة تبقى بالترتيب
  المنطقي الصحيح.
* زر الرجوع في Android يعمل عبر `on_keyboard` وسجل تنقّل داخلي.
* صور مراجعة الواجهة (420×880) في `artifacts/ui/`، ويُعاد توليدها عبر
  `.ui_review.py` على سطح المكتب باستخدام Xvfb.

## التشغيل على الحاسوب

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python main.py
```

قاعدة البيانات الافتراضية على سطح المكتب:
`~/.debt_manager_pro/debt_manager.db`، ويمكن تغييرها بمتغير البيئة
`DEBT_MANAGER_DB` (مفيد للاختبار والنسخ الاحتياطي).

## بناء APK

```bash
pip install buildozer cython
buildozer -v android debug
```

(Kivy 2.3.1 + KivyMD 1.2.0 + arabic-reshaper + python-bidi كلها ضمن
`requirements` في `buildozer.spec`.)

### البناء عبر GitHub Actions

يوجد Workflow باسم **Android Debug APK** في
`.github/workflows/android-debug-apk.yml`. شغّله من تبويب **Actions** ←
**Android Debug APK** ← **Run workflow**، أو ادفع إلى الفرع `build`
(`git push origin HEAD:build`) ليبدأ البناء نفسه دون فتح الواجهة.

* يثبّت Java 17 وPython 3.11 ومتطلبات Buildozer على `ubuntu-latest`.
* يبني `buildozer -v android debug` ويحفظ السجل في `buildozer-build.log`.
* يرفع Artifact باسم `debtmanagerpro-debug-apk` يحتوي `bin/*.apk` وسجل البناء،
  ويُرفع السجل أيضًا عند فشل البناء.
* يخزّن `~/.buildozer` (SDK/NDK) مؤقتًا لتسريع البناءات التالية.

نسخ البناء المثبَّتة في `buildozer.spec` (تغييرها قد يعيد أخطاء الترجمة):

* Python لـAndroid: `3.13.5` (الافتراضي 3.14 أقدم من دعم Kivy 2.3.1).
* `python-bidi==0.4.2`: آخر إصدار بايثون خالص؛ 0.6.x إضافة Rust لا تُبنى هنا.
* `android.ndk = 28c` مع `android.ndk_api = 24`: رؤوس bionic لا تعرّف
  `preadv` لهدف API 23، وملف `AndroidManifest` يبقى `minSdk 23` عبر
  `--allow-minsdk-ndkapi-mismatch`.
* `p4a.commit = d2ee8c5`: يمنع تلف pip داخل venv البناء.

الـAPK الناتج للتثبيت التجريبي على Android 6.0+ (minSdk 23)، ومقاسه نحو 48MB
لأنه يضم معماريتَي `arm64-v8a` و`armeabi-v7a`.

لتثبيت الـAPK على هاتف واختبار الشاشات السبع وRTL وإدخال العربية خطوة بخطوة،
اتبع [docs/TEST_ANDROID_AR.md](docs/TEST_ANDROID_AR.md).

## قرارات مهمة

1. **المبالغ**: تُخزَّن كأعداد صحيحة بالوحدات الصغرى (`amount_minor`) وتُحسب
   بـ `Decimal` فقط. لا يوجد `float` في أي مسار مالي.
2. **العملات**: كل دين بعملة واحدة، والإجماليات تُعرض لكل عملة على حدة.
   تحويل العملات مؤجَّل (جدول `exchange_rates` جاهز لكنه غير مستخدم).
3. **الهاتف**: ثلاث قيم منفصلة: `original_phone` (كما أُدخل)،
   `display_phone` (للعرض)، `phone_key` (للمقارنة). لا يُضاف رمز دولة أبدًا،
   ولهذا لا يمكن اعتبار `0770…` و `+964770…` رقمًا واحدًا تلقائيًا؛ قاعدة
   البيانات تمنع تكرار المفتاح المنظَّف، والخدمة تكشف التشابهات (لاحقة ≥ 7
   أرقام) للمراجعة اليدوية.
4. **الحذف**: حذف المدين يحذف ديونه ودفعاته بالتتابع (Cascade) لكن تُكتب نسخة
   JSON كاملة في `audit_logs` أولاً، فلا يضيع السجل المحاسبي بصمت.
5. **الأقساط**: خطة الأقساط جدول زمني لا يغيّر الرصيد؛ الدفعات هي مصدر الحقيقة
   المالي. لا يمكن تعديل مبلغ/عملة دين له خطة، ولا إنشاء خطة ثانية.
6. **الحالة**: تُخزَّن حالة الدين وتُعاد حسابها بعد كل دفعة داخل نفس المعاملة؛
   التأخير يُشتق من التاريخ عند العرض فقط.

## قيود حالية

* **الواجهة لم تُشغَّل رسوميًا في بيئة التطوير هذه** لعدم وجود X server أو
  محاكي Android؛ تم التحقق من تجميع ملفات Kivy/Python ومن توافق خصائص
  KivyMD 1.2 مع الكود، والتحقق الكامل من منطق الأعمال وقاعدة البيانات عبر
  الاختبارات. يلزم تشغيل `main.py` على جهاز/محاكي لمراجعة التنسيق البصري.
* لا إرسال رسائل SMS أو إشعارات بعد (المرحلة 3).
* لا نسخ احتياطي/تصدير/تقارير بعد.
* لا يمكن تعديل الدفعات أو حذفها من الواجهة بعد تسجيلها (غير مطلوب في هذه
  المرحلة)، ويمكن حذف الدين أو المدين كاملًا مع تسجيل ذلك في التدقيق.
